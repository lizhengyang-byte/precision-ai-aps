# 05 · 部署与实施

## 一、环境要求

- Python 3.11+（已在 3.12 验证），Node 仅用于前端语法检查（可选）
- 依赖：fastapi、uvicorn、sqlalchemy、ortools（可选但强烈建议）、httpx、pytest
- 数据库：默认 SQLite（单车间够用），并发超 20 人建议 PostgreSQL

## 二、本地启动

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

打开 `http://localhost:8000`，首次启动自动建库、写入演示数据并完成一次排产。

命令行演示：

```bash
python scripts/demo.py --plot   # 打印指标 + ASCII 甘特图，并导出 docs/images/gantt-demo.*
```

测试：

```bash
pytest -q     # 引擎约束、API、AI 解析共 12 项
```

## 三、容器化

```bash
docker compose up --build     # 暴露 8000，数据挂载 ./data
```

环境变量（`.env.example`）：`DATABASE_URL`、`AUTO_SCHEDULE_ON_START`、`LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`、`SOLVE_TIME_LIMIT`。

## 四、上线四步

1. **主数据导入**（第 1 周）：设备台账、人员技能矩阵、产品工艺路线、在制订单；技能等级由班组长与工艺员共同评定，避免“人人 L4”。
2. **双轨运行**（第 2~3 周）：系统计划与 Excel 计划并行，每日对比差异，校准标准工时与效率系数。
3. **单轨切换**（第 4 周）：以系统版本为准下发工单，报工改由看板/扫码录入，冻结机制启用。
4. **滚动运营**（持续）：每日早会看风险雷达，异常用自然语言登记并重排，每周复盘版本 diff。

## 五、验收指标（对照调研基线）

| 指标 | 基线 | 目标 |
| --- | --- | --- |
| 按期交付率 | 78% | ≥ 90% |
| 单次重排耗时 | 40~90 min | < 1 min |
| 计划变更遗漏 | 每周 2~3 处 | 0（diff 逐条可查） |
| 瓶颈设备利用率 | 未量化 | 可视化，稳定在 80%~90% |
| 技能错配返工 | 每月 3~5 次 | ≤ 1 次 |

## 六、风险与对策

- **标准工时不准**：先双轨校准，允许按设备效率系数修正；
- **技能评定主观**：用首件合格率与返工率反向校准等级；
- **求解规模**：单次 22 道工序/9 设备在 8s 内得出近优解，扩到 200 道工序建议按产品族分窗滚动求解；
- **人员抵触**：看板只做“建议 + 可覆盖”，保留计划员最终决策权。

## 七、后续路线

1. 报工扫码/设备数据采集（MTConnect/OPC UA）接入，实现自动进度；
2. 换型时间矩阵与刀具寿命约束；
3. 多车间/外协工序联合排产；
4. 基于历史版本的策略效果学习（从规则评分过渡到轻量模型）。
