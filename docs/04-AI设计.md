# 04 · AI 智能化设计

AI 在本系统里不是“接个大模型就完事”，而是四个可解释、可回退的决策模块。

## 一、排产求解模型（CP-SAT）

决策变量：每道工序 k 的开工时刻 `s_k`、可选设备 `m_k`、可选人员 `o_k`（区间变量 + 可选性字面量）。

硬约束：

- 工序先后：`s_next ≥ s_cur + duration`；
- 设备/人员不重叠：同一资源上的区间不重叠（NoOverlap）；
- 准入：设备类型、精度、人员技能等级均满足工序要求；
- 班次窗口：`AddLinearExpressionInDomain` 限定工序起止落在同一班次内；
- 冻结：已开工工序固定到原设备/人员/时刻，并占用资源；
- 不可用区间：故障/缺勤时段设备与人员禁排。

目标函数：

\[
\min\ \ 100\sum_o w_o T_o + 2\,C_{max} + \sum_i s_i
\]

其中 \(T_o\) 为订单拖期分钟、\(w_o\) 为优先级权重、\(C_{max}\) 为完工跨度。四档策略仅调整这三项权重（交期优先把拖期权提到 250，效率优先把跨度权提到 30），模型结构不变，便于对比与回退。

## 二、策略推荐（可解释规则）

先用启发式做一次“预演”，提取四个因子：加权拖期风险、瓶颈设备负荷、品种掺杂度、紧急订单数；再用规则选择策略并输出置信度：

- 拖期占比 ≥ 25% → 交期优先（置信度 0.6 + 拖期占比）；
- 否则瓶颈利用率 ≥ 90% → 产能效率优先；
- 否则产品族 ≥ 4 且平均批量 ≤ 80 → 换型最少；
- 否则 → 均衡排产。

每个因子都带原始数值与“怎么读”的说明，计划员可以不同意并手动覆盖。

## 三、交付风险雷达

- **订单级**：按计划完工与交期的缓冲分级：< 0 为高、< 4h 为中、其余为低，并指出该单占用最满的设备；
- **设备级**：Kingman 排队近似估计期望排队时长：

\[
W_q \approx \frac{\rho}{1-\rho}\cdot\frac{E[S]}{2}
\]

利用率 > 90% 标为高负荷，建议预留 10%~15% 插单缓冲；
- **技能级**：某类工序仅 1 名合格人员时标记单点依赖，建议跨岗培训。

## 四、中文指令解析（NLU）

规则优先：意图词典（重排/加急/故障/缺勤/批量/查询）+ 正则实体（设备编码、人员+请假、时长、日期、数量、订单号）。输出 `intent + entities + explanation`，前端先展示“我理解成了什么”再执行，避免误操作。无法识别且配置了 API Key 时，才调用大模型润色回答（仅回答，不直接改计划）。

## 五、变更影响解释

版本 diff 以 `task_key` 对齐，分四类：`added`（新增）、`removed`（移出）、`changed`（换机/换人/改期）、`kept`（不变），并附前后对比。自然语言执行后自动回传“多少道工序变了”，把“黑箱重排”变成可审阅的变更单。

## 六、降级与边界

| 场景 | 行为 |
| --- | --- |
| ORTools 未安装 | 自动使用列表调度启发式，接口字段不变，solver 标记 heuristic |
| 求解超时 | 返回当前最好可行解，并写入 warnings |
| 无可用设备/人员 | 工序不排入，计入 unscheduled 并在雷达中提示 |
| 无 LLM Key | 全部 AI 能力仍可用（纯规则），不降级 |
