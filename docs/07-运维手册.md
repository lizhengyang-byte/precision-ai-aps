# 07 · 运维手册

面向车间 IT 或集成商，覆盖部署、备份、升级、监控与故障处置。

## 一、部署形态

| 场景 | 方案 | 数据库 | 并发建议 |
| --- | --- | --- | --- |
| 单车间试点 | 单机 uvicorn + SQLite | `sqlite:///data/aps.db` | < 20 人 |
| 多车间/多角色 | Docker Compose（API + PostgreSQL 16） | `postgresql+psycopg://...` | 20–100 人 |
| 高可用 | 前置 Nginx/TLS，API 多副本，PG 主备 | PostgreSQL | > 100 人 |

最小生产配置：

```bash
cp .env.example .env
# 必填：AUTH_SECRET（≥32 位随机）、ADMIN_PASSWORD、POSTGRES_PASSWORD
docker compose up -d --build
curl -fsS localhost:8000/readyz
docker compose logs -f api
```

反向代理需转发 `X-Forwarded-*`，并保证 `/healthz` 不被鉴权拦截（当前实现即为公开）。

## 二、配置项

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `DATABASE_URL` | SQLite | 生产用 PostgreSQL，需安装 `psycopg`（已在 requirements） |
| `AUTH_REQUIRED` | 1 | 置 0 仅用于离线演示，生产禁止 |
| `AUTH_SECRET` | 无 | 令牌签名密钥，变更后所有会话失效 |
| `AUTH_TOKEN_TTL_SECONDS` | 43200 | 令牌有效期 |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | admin / ChangeMe@2026 | 仅在账号表为空时创建 |
| `FREEZE_HORIZON_MINUTES` | 120 | 冻结窗口，按车间实际换班节奏调整 |
| `SOLVE_TIME_LIMIT` | 20 | CP-SAT 单次求解上限（秒） |
| `CORS_ORIGINS` | * | 生产建议改为具体域名 |
| `LOG_LEVEL` | INFO | 访问日志与错误日志级别 |

## 三、备份与恢复

SQLite：

```bash
sqlite3 data/aps.db ".backup 'backup/aps-$(date +%F).db'"
```

PostgreSQL：

```bash
docker compose exec -T db pg_dump -U aps aps | gzip > backup/aps-$(date +%F).sql.gz
gunzip -c backup/aps-2026-11-28.sql.gz | docker compose exec -T db psql -U aps aps
```

建议：每日全量 + 保留 30 天；升级前额外做一次快照。`audit_logs` 与 `schedule_versions` 是追溯依据，不可裁剪。

## 四、升级流程

1. 备份数据库；
2. 拉取新镜像/代码，`docker compose up -d --build`；
3. 观察 `docker compose logs -f api` 与 `/readyz`；
4. 首次登录验证：`/api/auth/me` → 登录 → 打开看板 → 触发一次试排；
5. 若异常，回退镜像并恢复备份（表结构新增表为增量，回退不会丢历史排产数据）。

## 五、监控与告警

- 存活：`GET /healthz`（进程与求解器状态）；
- 就绪：`GET /readyz`（数据库连通性，失败返回 503）；
- 指标：`GET /metrics`（请求数、错误数、平均延迟、CP-SAT 可用性），可直接被 Prometheus 抓取；
- 日志：所有 `/api` 请求带 `X-Request-ID`，报错堆栈只进日志、不回前端；
- 建议阈值：5xx 比例 > 1%、P95 延迟 > 800ms、求解耗时 > 30s、磁盘使用 > 80% 触发告警。

## 六、故障处置

| 现象 | 排查 | 处置 |
| --- | --- | --- |
| 登录 401 | 口令错误累计 5 次会锁定 60s；`AUTH_SECRET` 是否变更 | 等待锁定解除；管理员重置口令 |
| 计划无法发布 | 查看 `/api/plan/state` 的 status | 按状态机补提交/审批；应急由 admin 直接发布 |
| 排产超时 | 看响应 `metrics.warnings`、订单/工序规模 | 提高 `SOLVE_TIME_LIMIT`，或按产品族拆分排产 |
| 甘特图空白 | 是否已发布版本、`/api/schedule/current` 是否为空 | 先执行一次排产；检查浏览器控制台 |
| 数据库连接失败 | `docker compose ps`、PG 健康检查 | 恢复 db 容器；确认 `DATABASE_URL` 与密码 |
| OEE 异常偏低 | 性能率按有效班次口径，周末/夜间不计 | 属预期；接入实际节拍后再评估 |

## 七、安全加固清单

- [ ] `AUTH_REQUIRED=1`，`AUTH_SECRET` 使用随机 32 字节并纳入密钥管理；
- [ ] 首次登录立即改密，删除或停用演示账号；
- [ ] `CORS_ORIGINS` 收敛到公司域名；
- [ ] 前置 TLS，禁止 8000 端口直接暴露公网；
- [ ] 数据库仅内网可达，定期备份并做恢复演练；
- [ ] 每季度导出审计日志归档，保留至少 1 年。
